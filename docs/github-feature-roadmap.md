# 课伴：GitHub 同类项目对比与分期改进建议

> 历史规划：本文的“当前状态”对应当时版本，备份恢复、题库、OCR 等已有后续实现。请以 [0.3 更新与验收](UPDATE-0.3.md) 为当前依据。

调研日期：2026-09-26。范围：15 个公开 GitHub 仓库。以下竞品功能依据其仓库 README 描述，属于项目方声明，并非逐项安装验收；课伴现状依据本仓库代码与 `README-PORTABLE.md`。本报告是功能规划，不意味着这些仓库的实现质量相同。

## 一、当前项目的起点

课伴已经具备课程导览与逐章讲解、PDF/DOCX/TXT/Markdown 上传及文本抽取、限定资料范围的 AI 问答及原文引用、笔记与双向链接、知识图谱、快速查找、主动回忆、手动与 AI 草稿复习计划、课程考试日期、回收站、Markdown 笔记导出和 JSON 数据下载。建议保留这些已有路径，围绕真实学习行为补齐闭环。

需要特别区分：当前资料检索按词项命中原文片段排序，暂不是语义检索；引用可以打开原文件页码，但还不是在阅读器里精确定位并高亮原句。当前复习采用笔记级“答对/没答对”及 1、3、7、14、30 天固定间隔，尚无独立题目、错题统计和记忆模型。JSON 备份可下载，但界面未提供导入恢复，且原始上传文件需另外保存。

核对位置：`lib/knowledge.ts`、`lib/note-navigation.ts`、`app/api/chat/route.ts`、`app/page.tsx`、`README-PORTABLE.md`。

## 三、最值得补的缺口：按收益排序

1. **练习与错题闭环（最高优先级）**：当前能够讲解和回忆笔记，却没有结构化题目、作答、判分、错因与再练入口。建议先做手工出题和编辑，再做 AI 从指定资料生成草稿；错题直接加入复习队列。
2. **可靠备份与恢复（最高优先级）**：当前 JSON 只保存原文件链接，换电脑后链接可能失效。需要包含文件的可验证备份包、导入预览、冲突处理和一次实际恢复演练。这是便携版最明显的可靠性缺口。
3. **原文定位与扫描件处理（高优先级）**：保留现有引用编号，补原文件页内定位/高亮；扫描 PDF、拍照资料应显示“未识别”，经用户触发 OCR 后才参与问答。不能把通用 AI 讲解当作教材证据。
4. **检索质量（高优先级）**：目前笔记搜索、问答检索依赖字面词命中。先建立覆盖资料、笔记和问答的统一搜索与召回评测集，再决定是否加本地向量索引与混合排序；避免直接引入复杂数据库而没有可测收益。
5. **复习策略与考试导向（中优先级）**：先记录题目级作答历史和难度，再考虑 FSRS。仅靠现有“答对/没答对”两档数据，直接切换算法难以真正个性化。现有考试日期可驱动“考前薄弱章节”视图。

## 四、分期路线

### 1.0：先让“学完能练、资料能救回来”

**目标**：课程章节有可用题目；学生做错后能再次练习；迁移电脑时能恢复数据。

1. **题目与作答**：新增题目对象，关联课程、章节、资料片段/笔记。首批支持选择题、判断题、简答题；答案与解析分开显示。允许手工创建、编辑、删除；AI 仅生成待确认草稿。每次作答保存时间、答案、是否正确、自评和来源版本。
2. **错题页与再练**：按课程/章节筛选错题，显示错因标签（概念不清、计算错误、审题失误等）；支持“重做原题”和“同知识点再来一题”。错题可进入现有复习计划或今日待复习，不另开平行日程。
3. **完整备份恢复**：导出包含结构化数据及原文件的备份包；导入前显示课程、笔记、文件数及冲突预览；先做整体恢复和明确的替换确认，避免一开始做复杂合并。恢复后自动校验文件哈希、引用可打开、课程/笔记数一致。
4. **小型验收样本**：选 2 门真实课程、各 1 份文本 PDF 与扫描 PDF、各 10 道题。能走通“资料→出题/编辑→作答→错题→再练”，再用另一台电脑或全新数据目录恢复完整备份。

**完成标准**：学生无需 AI 也能手工建题和练习；AI 草稿不会直接覆盖资料或标准答案；导入后所有原文件和引用能重新打开。

### 2.0：提高资料可信度与练习针对性

**目标**：面对大量课件仍能找到依据，并把错误聚合成薄弱知识点。

1. **资料阅读与引用**：页码跳转升级为段落定位/高亮；答案、题目、笔记都保存原文锚点。资料更新后标出失效引用，允许人工重新绑定。
2. **OCR 与格式扩展**：优先扫描 PDF 和图片；PPTX 只有在用户课程确实常用时再加入。显示每页识别状态与置信提示，支持人工修正；未识别页不假称已纳入问答。
3. **混合检索**：保留现有词法检索作基线，增语义候选与重排。用真实课程问题建立 30–50 条评测，记录相关片段命中率、无依据回答率、响应时间和模型成本。只有实际改善再默认启用。
4. **薄弱点面板**：以章节/知识点汇总答错率、最近练习、仍未解决的错因，向现有计划推荐 3–5 项具体任务；推荐可编辑，并说明依据。

**完成标准**：点击引用可看到原句；扫描件识别失败有明确提示；推荐任务能追溯到具体错题，不把“学了多久”当作“掌握了”。

### 3.0：成熟复习与可移植生态

**目标**：题量和长期记录足够后，再做更精细的调度与跨工具流转。

1. **卡片与间隔复习**：从题目/错题生成问答卡和填空卡；支持四档自评、每日新卡与复习上限；保留旧复习记录并提供迁移预览。是否采用 FSRS 取决于题目级历史是否充足以及用户是否愿意持续评价。
2. **考前模拟**：按课程章节和难度组卷，支持限时、考后解析和薄弱点回写。主观题 AI 评分显示依据与不确定性，允许人工改分。
3. **开放导出**：笔记 Markdown、题库 CSV、卡片 Anki 兼容格式；导出的题目要附课程、章节、来源与许可说明。优先做好导出，跨设备实时同步最后再考虑。
4. **可选集成**：如果真实用户需要，再评估校历/作业日程、PPTX、录音转写、移动端；不要把社交、游戏化、播客等作为默认主线。

**完成标准**：隔几个月返回同一门课仍能延续复习；题库导出后可在外部工具继续使用；模拟考试的错误能回流到薄弱点与下一轮计划。

## 五、实施次序与判断方式

建议依赖顺序：**备份恢复与题目数据模型 → 手工/AI 草稿出题 → 错题与再练 → 来源锚点 → OCR/检索 → 薄弱点计划 → 长期调度与模拟考**。用户价值优先于功能数量。

不要照搬的功能：复杂社交学习小组、花哨统计、自动生成播客/视频、全自动 AI 写入知识库、实时多端协作。它们在 1.0 阶段会显著增加维护与数据风险，却不能解决“能否学会、练会、找回资料”的核心问题。

建议持续观察四个指标：课程资料中可检索页占比；题目从创建到完成的比例；错题二次练习后的正确率；备份恢复成功率。前两项检验入口是否可用，后两项检验学习闭环和数据可靠性。
