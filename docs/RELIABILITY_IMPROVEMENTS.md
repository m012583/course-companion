# 数据保护与学习流程改进（2026-09-24）

本说明更新此前验收中的相应限制。真实用户试用和真机软键盘仍待实际参与者完成。

## 当前实现

1. 任务、对话、资料与课程、笔记均支持回收站及撤销。恢复检查所属课程和标识冲突；对话删除时保留笔记关联以便恢复。附件不物理删除，以保护引用与快照。
2. 工作区发生保存时，间隔至少 30 分钟记录修改前自动快照，保留最近 20 份；快照与主记录变更同一事务完成。恢复前快照单独保留。设置的数据管理可下载快照，按完整备份预览流程恢复。本机快照不防磁盘损坏。
3. 草稿继续在浏览器暂存，同时纳入本机工作区保存、完整备份及附件映射。恢复备份替换草稿；旧版备份缺少草稿时恢复为空。恢复前保存当前工作区。设置中无近 7 天下载记录时提醒异地备份。
4. 图片支持 PNG/JPG/WebP；扫描 PDF 点击“识别扫描文字”，仅对无文字层页面识别，单次最多处理前 20 页。文字 PDF 原上限 500 页，正文上限 40 万字符。识别与语言包在本机运行，组件首次使用按需加载。保留页码，允许逐段人工校正；原文件和已保存历史引文不改写。
5. 复习按三档安排：没答对次日；吃力保留连续次数，取答对间隔的一半且至少 2 天；答对增加次数，按 3、7、14、30、60 天逐步延长。显示下次日期，支持撤销和手动改期。该规则不是经过用户研究验证的记忆模型。
6. AI 提示进一步区分“资料依据”和“补充解释”，强调条件、充分必要关系、资料指令隔离和无依据不编造。

## 验证与实测边界

- 类型、lint、领域、构建以及原增删改查、草稿、布局、真实隔离 D1/R2 流程回归。
- 自动快照下载与节流、旧版本写入冲突不覆盖草稿、备份草稿附件标识映射、各类回收恢复冲突与所属课程检查。
- 本机 Edge 使用自编中英文 PNG 和单页图片 PDF，真实 OCR 识别并保存校正；捕获网络请求确认 OCR 无外部连接。不是复杂教材、手写或公式准确率测试。
- 新增 8 道自编真实模型题，8 次请求完成，7 道达到核心预期。R04 因只有一个中文关键词命中而被检索阈值过滤，未得到360米的预期答案；完整保留失败，未将它改写为成功。模型提示改进无法补偿检索漏失。结果位于 evaluation/reliability-live.json，非独立盲评。
- 自编 1000 条笔记、40 份资料、4000 个片段，约 4.8 MB JSON：本次本机开发服务打开笔记页 1359 ms，搜索定位 170 ms；模拟写接口延迟 600 ms。单次测量不是生产容量、并发或低端手机保证。原始记录 evaluation/scale-report.json。

## 使用与复现

执行 npm ci 后，npm run dev / build 自动运行 tools/prepare-ocr.mjs，将锁定依赖的 OCR runtime 和中英文数据复制到 public/ocr。生成文件不进入 Git，完整安装后识别不依赖外部 CDN。来源与 API 用法：https://github.com/naptha/tesseract.js ，许可证随依赖保留。

测试入口：test:domain、test:comfort、test:crud、test:layout、test:ocr、test:protection、test:scale。浏览器需设置 PLAYWRIGHT_MODULE，默认隔离服务3015；test:protection 必须显式授权隔离测试库。eval:reliability 需 COURSE_KB_LIVE_EVAL=self-authored-only，读取本机环境配置，仅发送自编内容，产生真实服务用量，不输出密钥。
