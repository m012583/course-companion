# 0.4：连续学习与阅读工作区

本次以 0.3 为基线，围绕“教材 → 核对题目 → 作答 → 错因 → 复习”更新。升级前已备份源码、完整 Git 历史和含附件学习数据；原始开发历史保持不变。

## 已实现

| 位置 | 新行为 |
| --- | --- |
| 课程导航 | 学习概览、教材阅读、AI 问答、练习与错题；课程删除位于“更多”，保留确认与回收站 |
| 教材阅读 | 默认聚焦正文，资料管理可展开；按段保存阅读位置；桌面教材和问答并排，窄屏切换；选段提问、带依据记笔记 |
| 原文引用 | 历史引文保留；当前原文可定位时，直接进入对应教材段落；PDF 沿用页码跳转 |
| 快速自测 | 按章节或自选知识点查找依据；AI 生成后直接进入题库草稿，核对后立即练习 |
| 出题过程 | 服务端发送真实“检索依据、生成草稿、检查格式与引用编号”阶段；可取消或重试；未完整生成不保存 |
| 练习反馈 | 下一题、错因对应建议、重新讲解、生成同类练习；历史题目快照和作答独立保存 |
| 复习 | 答错默认今天回看、两天后重练；答对默认四天后重练；预览中可改日期；关联题目可直接打开 |
| 今日学习 | 继续教材阅读、待核对题目与待巩固错题；样本不足时不推断整门课程掌握程度 |
| 设置 | 检索评测工具移入设置；教材校准移入教材阅读；版本介绍只在首页出现并可关闭 |

资料、草稿、练习和复习仍使用同一工作区的版本冲突保护。跨课程同名但无附件编号的资料在选择器中使用课程限定标识，避免误选其他课程的同名内容。

## 兼容与回退

新增 `course.reading`、`studyLab.flow` 和复习任务的可选 `questionId`。原 0.3 数据无需手工处理；备份格式仍为 `course-kb-bundle` 第 2 版。阅读位置中的附件 ID 参与导入重映射。旧自测保留，可从生成记录继续导入核对，不伪造旧作答为新的练习记录。

回退步骤：导出新版含附件迁移包；停止新版服务；使用 0.3 源码与更新前的数据备份启动。不要只降低包版本后继续写入新版数据，也不要删除 `.wrangler/`。

## AI 评测

- 固定题集：`evaluation/learning-benchmark-v1.json`，80 道自编问题与人工参考答案。原有 36 题作为 development，新写 44 题作为 validation；运行前冻结并记录文件 SHA256。
- 本次执行的是本地检索对照，不是独立盲测、真实模型答案准确率或学习效果研究。公式和表格用文本表示，不评价扫描公式识别。
- 新增 32 道有依据问题：旧检索与现检索均在前五条找齐全部预期片段；12 道无依据问题均有 8 道返回空。其余 4 道命中相关背景，不能据此认定答案可从资料中得出，也不能把空结果率当成模型拒答率。
- 两种方案在本题集未显示覆盖优势，本次保留现有检索策略，没有引入未经验证的向量库。
- `npm run evaluate:learning` 重跑检索。真实 AI 运行前在本机配置服务，设置 `COURSE_KB_EVAL_URL`，执行 `node tools/evaluate-learning.mjs --ai --limit=5`。需要全量时显式使用 `--limit=80`。
- 真实模型结果写入忽略目录 `work/learning-ai-review.json`，需要人工填写答案正确性、引用支持性和无依据处理；费用按服务商账单记录。没有密钥时脚本拒绝调用，不生成虚构分数。

## 验收与剩余事项

自动化涵盖流程导入幂等性、软删除不复活、历史不覆盖、单知识点生成校验、SSE 成功与失败、阅读位置迁移及复习规则。浏览器记录见 `evaluation/learning-ui-v1.json`；模拟桌面、768 和 390 像素视口，不等同于实体手机测试。

当前 AI 服务未配置密钥，新一轮真实模型评测未执行。第二台实体电脑、真实手机软键盘、3–5 位同学试用需要现实设备与参与者，尚未完成。相关任务卡和记录表见 `USER-TRIAL.md`。

## 依赖修复

同步升级 React / React DOM / RSC、vinext、Cloudflare 插件、Wrangler 和格式化工具，更新有补丁的间接依赖。对 KaTeX 统一到根目录版本，对 sharp 和 fflate 使用已发布的补丁覆盖；这些覆盖有兼容风险，必须随构建、公式、文档读取和实际浏览器检查验证，后续上游修复后再移除。

官方审计从 29 项（3 critical、15 high、7 moderate、4 low）降至 12 项（0 critical、9 high、3 moderate、0 low）。剩余主要来自 braces 与 sprintf-js 及其依赖链；不是 12 个独立可从界面利用的漏洞，也不意味着可以直接安全部署公网。详见 `evaluation/dependency-audit-0.4.json`。

公网演示仍为待评估项：需单独完成访问控制、数据隔离、调用额度限制和剩余风险处置。
